## 2. Анатомия карточки задачи

Каждая задача в `.md` файле представляет собой автономный блок со следующей строгой структурой:

```markdown
## Задача 14: Формирование матрицы {#task-014-python-algorithm-matrix}
**Источник:** [Решаю задачи с собеседований Python Backend стажёр](https://www.youtube.com/watch?v=dzBrrX3Osks)

### Условие
Дано два числа n и m. Необходимо сформировать матрицу размером n на m...

### Код задачи
```python
def foo():
    pass
```

### Решение кандидата
Кандидат предложил решение с использованием вложенных циклов...

### Эталонное решение (AI)
Перед нами отличная практическая иллюстрация теории...

#### 1. Вариант (Классические циклы)
Текст разбора...
```

### Главные элементы:
1. **Заголовок `## ` (H2):** Обязан содержать тему, номер и семантический атрибут Extended Markdown `{#slug}`.
2. **Семантический slug:** Имеет формат `[тип]-[номер]-[язык/технология]-[категория]-[суть_коротко]`. За счет плагина `attr_list` в `mkdocs.yml` тег `{#slug}` не виден на экране, а превращается в HTML-атрибут `<h2 id="slug">`.
3. **Фиксированные секции H3 (`###`):**
   - `### Условие`
   - `### Код задачи` (опционально)
   - `### Решение кандидата`
   - `### Эталонное решение (AI)`

## 3. Критические табу и правила для агента (MUST OBEY)

1. 🚫 **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО использовать `#` и `##` внутри тела задачи!**
   - Заголовок `## ` (H2) обозначает **ТОЛЬКО** начало новой карточки.
   - Вложенные подсекции внутри ответа AI или условия должны использовать **`#### ` (H4)**, **`##### ` (H5)** или жирный текст `**1. Вариант**`.
   - *Нарушение этого правила разбивает одну задачу на несколько в MkDocs TOC и ломает клиентский JS-скрипт (`extra.js`).*

2. 🚫 **НЕ СТИРАТЬ И НЕ ПОРТИТЬ `{#slug}` в заголовках H2:**
   - При переименовании или правке заголовка `## Задача N: ...` всегда сохраняй семантический атрибут `{#slug}` в конце строки.

3. 🚫 **НЕ ИСПОЛЬЗОВАТЬ ad-hoc стили или несовместимую разметку:**
   - Все `### Решение кандидата` и `### Эталонное решение (AI)` автоматически оборачиваются на фронтенде в сворачиваемые блоки `<details class="script-details">`. Не создавай такие html-теги вручную в Markdown-файлах.

## 4. Регламент поиска и безопасного редактирования

### Поиск задач:
- **Приоритетный путь (100% точность):** Выполнять точный поиск по семантическому тегу `{#slug}` через `grep_search` (например, `Query: "{#task-014-python-algorithm-matrix}"`).
- **Запасной путь:** Поиск по точному тексту названия задачи `## Задача N: Название`.

### Редактирование задач:
1. Перед правкой прочитать всю карточку целиком (от ее `## Задача N` до строки перед следующим `## Задача N+1`).
2. Использовать tool `replace_file_content` для замены ТОЛЬКО целевого блока (например, `### Эталонное решение (AI)`).
3. После редактирования проверить целостность соседних задач в файле.

## 5. Гибридная архитектура: Agent Skills + Ray Broker

### Принцип
- **Агент (IDE чат) = Мозг.** Читает Skills из `.agents/skills/`, принимает решения, показывает результаты пользователю, управляет стейт-машиной.
- **Ray Broker (`infrastructure/cli_broker.py`) = Мышцы.** Тупой параллельный исполнитель очередей. Без UI, без решений. Агент запускает и останавливает его по необходимости.

### Команды пользователя (слэш-команды в чате)
- `/add <URL>` → Агент читает `add-video/SKILL.md`. Для одного видео — сам выполняет пайплайн. Для плейлиста — запускает брокер.
- `/add doc <path>` → Агент читает `add-doc/SKILL.md`. Чтение и OCR PDF/изображений/текстов.
- `/rm <задача>` → Агент читает `remove-task/SKILL.md`. Безопасное удаление задачи из базы знаний.
- `/search "<query>" [limit]` → Агент читает `search-videos/SKILL.md`. Ищет и скачивает видео.
- `/review` → Агент читает `review-tasks/SKILL.md`. Показывает задачи из очереди, запрашивает апрув (с опциональным OCR скриншотов и выбором языка), запускает Эксперта.
- `/resume` → Агент читает `resume-broker/SKILL.md`. Запускает Ray-брокер фоном для обработки накопившихся задач.

### Поток данных
```
/add <url> (download.py) / /add doc <path> (ingest_doc.py)
  → raw_transcripts/*.vtt | *.txt
    → mine.py → .cache/01_pending_triage/*.json
      → [АПРУВ В ЧАТЕ + OCR СКРИНОВ + ВЫБОР ЯЗЫКА]
        → solve.py → .cache/02b_pending_testing/*.json
          → test_runner.py → .cache/03_pending_final/*.json
            → [АПРУВ В ЧАТЕ]
              → publish.py → docs/livecoding/python.md
```
