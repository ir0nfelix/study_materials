# Skill: Просмотр и апрув задач (`/review`)

## Триггер
- Пользователь пишет: `/review`
- Или автоматически вызывается после успешного `/add`

## Инструменты (скрипты)
- `agents/03_expert/solve.py <path_to_json>` — генерация эталонного решения через LLM
- `agents/04_facilitator/test_runner.py <path_to_json>` — тестирование сгенерированного кода
- `agents/05_publisher/publish.py <path_to_json>` — публикация карточки в MkDocs

## Переменные окружения
- `OPENROUTER_API_KEY` — читается из `.env` в корне проекта (используется в `solve.py`)

## Рабочий процесс

### Этап 1: Triage (Сортировка)
1. Прочитай все JSON-файлы из `.cache/01_pending_triage/`.
2. Для каждого файла покажи пользователю:
   - Заголовок задачи (`title`)
   - Условие (`condition`)
   - Исходный язык (`source_language`)
   - Источник (`source_file`)
3. **Опциональный OCR:** Спроси пользователя: *"Хотите прикрепить скриншоты с YouTube для распознавания кода задачи?"*
   - Если да — дождись изображений, извлеки текст кода (используя свои multimodal возможности) и добавь его в `condition`.
4. **Выбор языка:** Спроси пользователя: *"Оригинал задачи на **<source_language>**. На каком языке вы хотите эталонное решение?"*
   - Добавь выбранный пользователем язык в JSON-файл в поле `"target_language"`.
5. Спроси: *"Отправить эту задачу Эксперту? (да/нет)"*
6. Если `да` → перемести файл в `.cache/02_pending_expert/`.
7. Если `нет` → перемести файл в `.cache/99_rejected/`.

### Этап 2: Expert (Решение)
1. Для одобренной задачи запусти Эксперта:
   ```bash
   ./venv/bin/python agents/03_expert/solve.py .cache/02_pending_expert/<filename>.json
   ```
   Скрипт сам переместит файл в `.cache/02b_pending_testing/` после обработки.

2. Запусти Фасилитатора (тестирование кода):
   ```bash
   ./venv/bin/python agents/04_facilitator/test_runner.py .cache/02b_pending_testing/<filename>.json
   ```
   Скрипт переместит файл в `.cache/03_pending_final/`.

### Этап 3: Final Review (Финальный просмотр)
1. Прочитай JSON из `.cache/03_pending_final/`.
2. Покажи пользователю:
   - Условие задачи
   - Эталонное решение (AI) — поле `expert_solution`
   - Результаты тестов — поле `test_results`
3. Спроси: "Опубликовать в базу знаний? (да/нет/редактировать)"
4. Если `да` → перемести в `.cache/04_pending_publish/` и запусти:
   ```bash
   ./venv/bin/python agents/05_publisher/publish.py .cache/04_pending_publish/<filename>.json
   ```
5. Если `редактировать` → прими правки от пользователя, обнови JSON, вернись к шагу 3.

### Этап 4: Подтверждение
1. Сообщи пользователю: "Задача N опубликована в `docs/livecoding/python.md`."
2. Если запущен MkDocs (`mkdocs serve`), предложи проверить результат в браузере.

## Правила публикации (КРИТИЧНО)
Перед вызовом `publish.py` убедись, что решение от Эксперта:
- НЕ содержит заголовков `#` или `##` (только `###`, `####`, `#####`)
- Содержит блок кода с решением
- Имеет анализ сложности (Time/Space)

Полные правила разметки описаны в `.agents/AGENTS.md`, раздел 2-3.
